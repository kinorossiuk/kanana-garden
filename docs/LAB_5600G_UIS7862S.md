# 5600G · Codex · UIS7862S 제어 테스트 랩

## 목표

최종 목표는 UIS7862S 헤드유닛에서 한국어 음성으로 볼륨, 길안내, 음악을
제어하는 것이다. 개발 중에는 명령 해석과 Android 동작 실행을 분리한다.

```text
사용자 명령
   │
   ▼
5600G Kanana 명령 해석기
   │  strict action JSON
   ▼
UIS7862S Android 제어 브리지
   ├─ volume_*      → AudioManager
   ├─ navigation_*  → 검증된 navigation Intent
   ├─ media_*       → 활성 MediaSession
   └─ app_open      → 고정 app alias

최종 단계: 5600G 명령 해석기를 UIS7862S 내부 추론 backend로 교체
```

LLM은 shell, package 이름, 터치 좌표, URL을 생성하거나 직접 실행할 수 없다.
허용 action과 slots만 제어 브리지에 전달한다.

## 저장 위치와 보안 경계

1. 소스, 테스트, issue는 GitHub Public에서 관리한다.
2. 모델 가중치와 5600G 추론 캐시는 Git에 넣지 않는다.
3. OTA 바이너리와 원본 UIS7862S 캡처는 각각 `var/ota/`,
   `reports/uis7862s/`에 두며 Git에서 제외한다.
4. 한 재현 건에는 OTA 버전, Android build fingerprint, 앱 버전, Git commit,
   서버 model revision과 dtype을 함께 기록한다.
5. 차량이 움직이는 동안 개발용 테스트를 수행하지 않는다.

## 0단계: UIS7862S 제어 브리지 사전 검증

이 단계에는 LLM이 필요 없다. 먼저 장비와 펌웨어를 고정한다.

```bash
adb devices -l
kanana-garden uis7862s-doctor
```

SoC는 펌웨어에 따라 `UIS7862S` 대신 `UMS512`로 표시될 수 있다. 다음 표를
실제 대상 OTA마다 다시 확인한다.

| action | 우선 구현 경로 | 초기 합격 조건 |
|---|---|---|
| `volume_up/down/set/mute` | Android `AudioManager` | 음악 스트림이 실제로 변하고 UI 상태와 일치 |
| `navigation_start` | 설치 앱을 확인한 Intent adapter | 목적지가 보존되고 내비 앱이 정상 실행 |
| `navigation_stop` | 내비 앱별 공식/공급사 adapter | 진행 중 안내만 안전하게 종료 |
| `media_play/pause/next/previous` | 활성 `MediaSession` | 현재 재생 앱만 제어 |
| `app_open` | `navigation/music/settings` 고정 alias | 임의 package 실행 불가 |

일반 APK 권한으로 불가능한 동작은 접근성 화면 좌표로 우회하기 전에 공급사
서명 시스템 앱 또는 공식 앱 연동 권한을 검토한다. 펌웨어 UI가 바뀌면 깨지는
좌표 기반 자동화는 최후 수단이다.

현재 저장소는 action 계약, Android 제어 브리지 APK, ADB 진단 도구와 LTE
테스트 보고서 수신기를 제공한다. alpha APK 화면에서 PASS/FAIL을 기록하고
HTTPS로 제출할 수 있다. 상세 설정은 [LTE 보고서 수신](LTE_REPORTING.md)을
따른다.

## 1단계: 5600G 명령 해석 안정화

5600G 호스트에서 설치한다.

```bash
./ops/5600g/install.sh

# ~/.config/kanana-garden/server.env에서 KANANA_API_KEY와 HF_HOME 확인
./ops/5600g/run.sh
```

초기 기준은 Ryzen 5 5600G의 6개 물리 코어, CPU `float32`, 고정된 Hugging
Face revision이다. 서버는 생성을 직렬화하고 시작할 때마다 새 session UUID를
발급한다.

현재 작업 폴더에서 연결과 action 계약을 확인한다.

```bash
kanana-garden doctor

kanana-garden vehicle-command --input "볼륨 올려줘"
kanana-garden vehicle-command --input "강남역으로 길 안내해줘"
kanana-garden vehicle-command --input "다음 곡 틀어줘"
```

정상 출력 예시는 다음 형태다.

```json
{
  "action": "navigation_start",
  "slots": {"destination": "강남역"},
  "confidence": "high",
  "requires_confirmation": true
}
```

허용되지 않은 기능은 `unsupported`여야 한다. JSON 이외 설명, 알 수 없는
action, 임의 package/shell/좌표 필드는 CLI가 거부한다.

### 반복 기준선과 서버 재시작

```bash
kanana-garden server-baseline \
  --output reports/5600g-session-1.json

systemctl --user restart kanana-garden

kanana-garden server-baseline \
  --output reports/5600g-session-2.json

kanana-garden server-compare \
  reports/5600g-session-1.json \
  reports/5600g-session-2.json
```

두 baseline은 model·revision·dtype·recipe 해시가 같고 server session UUID가
달라야 한다. `vehicle-control-ko` sample은 기대 action 문자열뿐 아니라 전체
action JSON 계약도 재검산한다.

## 2단계: 5600G와 UIS7862S 연결

이 단계의 LLM은 여전히 5600G에서 실행한다. 흐름은 다음과 같다.

1. 텍스트 또는 음성 인식 결과를 5600G `vehicle-command` 경로에 전달한다.
2. action 계약 검증기를 통과한 JSON만 Android 제어 브리지에 전달한다.
3. 제어 브리지는 action별 고정 Android API/Intent adapter만 호출한다.
4. 실행 결과와 오류를 action ID, 앱 버전, OTA 버전과 함께 기록한다.

`requires_confirmation=true`, `confidence=low`, `unsupported`는 자동 실행하지
않는다. 통화·차량 설정·안전 관련 기능은 별도 허용 목록과 확인 절차 없이는
추가하지 않는다.

## 3단계: UIS7862S 완전 온디바이스

다음 조건을 모두 통과한 뒤 LLM 탑재를 시작한다.

- 5600G의 차량 제어 예제가 두 서버 세션에서 각각 3회 연속 통과
- `server-compare` 통과
- 볼륨·길안내·음악 제어 브리지가 실제 목표 OTA에서 통과
- Android ABI, RAM, 저장공간, 사용 가능한 CPU/GPU/NPU runtime을 고정
- 모델 revision, prompt, action schema를 고정

이후 양자화 후보를 만들고 `runtime-stability-ko-v1`으로 5600G 기준 출력과
비교한다. 최종 배포물은 한 번에 설치 가능한 APK 또는 APK+서명된 모델 팩을
목표로 한다. cold start, 명령 지연, 메모리 peak, 30분 반복, 재부팅, OTA 전후
회귀를 실제 장비에서 측정한다.

## 장애 캡처와 OTA

버그 재현 직후 캡처한다.

```bash
kanana-garden uis7862s-capture \
  --label issue-12 \
  --package com.example.vehicleassistant \
  --ota-version 2026.08.1
```

기본 번들은 logcat, dumpsys/proc 상태, 화면, 비식별 getprop, crash·ANR·OOM·
watchdog·thermal 후보와 파일 SHA-256을 포함한다. 전체 bugreport는 꼭 필요할
때만 추가하고 외부 공유 전 사람이 개인정보를 검토한다.

OTA는 공급사 URL과 SHA-256을 독립적으로 확인한 뒤 내려받는다.

```bash
make ota-download
kanana-garden ota-verify var/ota/2026.08.1/manifest.json
```

자동 플래시는 제공하지 않는다. 대상 보드·판매사·MCU, 롤백 이미지, 복구
절차, 안정적인 벤치 전원을 확인한 뒤 공급사 절차로 적용한다.

## LTE 테스트 결과 수신

UIS7862S가 LTE 외부망이고 USB 연결이 어려우면 DuckDNS+nginx 또는 Cloudflare
Tunnel의 공개 HTTPS hostname을 통해 현재 checkout으로 결과를 받는다. 어떤
방식이든 수신기는 `127.0.0.1:8762`에만 바인딩한다.

```bash
systemctl --user enable --now kanana-report-receiver
curl -fsS http://127.0.0.1:8762/health
```

APK가 제출한 원문과 해시 메타데이터는 `reports/uis7862s/inbox/`에 저장된다.
주소와 token을 공개 APK나 Git에 넣지 않는다.

## GitHub 운영

공개 저장소는 `https://github.com/kinorossiuk/kanana-garden`이다. push와 pull
request마다 Python 3.10/3.12에서 asset, report, catalog와 단위 테스트를
검사한다.

```bash
make test
make validate
git status --short --branch
git push origin main
```

원본 진단 번들, `.env`, API 키, OTA 바이너리는 공개 저장소나 이슈에 올리지
않는다. 이슈에는 검토·비식별화한 최소 로그, manifest 해시, OTA version,
build fingerprint와 관련 commit만 첨부한다.
